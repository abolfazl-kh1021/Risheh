# DEMO_ACCOUNTS.md — دستورالعمل حساب‌های دمو (M11)

> **هشدار صداقت:** این حساب‌ها فقط در نسخه‌ی نمایشی وجود دارند و فقط وقتی
> `DEMO_MODE=true` ساخته می‌شوند. بدون `DEMO_MODE` هیچ seed و هیچ کاربر
> پیش‌فرضی ساخته نمی‌شود (قانون scope rule ۶/۱۰). ادمین واقعی فقط با
> `bun run admin:create` ساخته می‌شود.

## سناریوهای تمرین دمو

1. **خرید تک‌فروشنده:** ورود خریدار → افزودن به سبد → `/cart` → تسویه → درگاه
   نمایشی (سه گزینه) → نتیجه → تایم‌لاین سفارش.
2. **سفارش چندفروشنده:** آثار از دو کارگاه به سبد؛ پس از پرداخت موفق،
   `/dashboard/orders` برای هر استادکار فقط زیرسفارش خودش را نشان می‌دهد.
3. **چرخه‌ی آگهی با کارمزد:** استادکار → آثار → «ارسال برای بازبینی» → فاکتور
   کارمزد پلن → درگاه نمایشی → صف بازبینی ادمین → انتشار با مهلت ۶۰ روز.
4. **سقف پلن:** با پلن رایگان (کارگاهی با پلن رایگان بسازید) تلاش کنید آگهی
   چهارم را بفرستید → پیام «سقف آگهی پلن شما پر است».
5. **تسویه:** استادکار → مالی → درخواست تسویه فقط از مانده «قابل تسویه»؛ ادمین
   تایید/واریز نمایشی.
6. **پیگیری مهمان:** خرید مهمان در `/cart` (بدون ورود) → پس از پرداخت
   `/track` با «شماره سفارش + موبایل».
7. **استعلام اصالت:** `/verify` با کد اثر نمونه (مثلاً RSH-9834) — متن شفاف:
   رکورد دیجیتال ریشه، نه گواهی آزمایشگاه مستقل.

## ریست داده دمو

```bash
# محلی
SEED_FORCE=1 bun prisma/seed.ts          # در پایگاه‌داده .env فعلی
# Docker
docker compose down -v && DEMO_MODE=true docker compose up -d --build
```

## ساخت ادمین واقعی (غیر دمو)

```bash
ADMIN_EMAIL='root@yourdomain.ir' ADMIN_PASSWORD='…' ADMIN_NAME='مدیر' \
  bun run admin:create
```
همیشه: درخواست عضویت عمومی هرگز نقش ADMIN نمی‌دهد (تست integration دارد).
